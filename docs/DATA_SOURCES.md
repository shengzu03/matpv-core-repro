# 数据获取与版本核对

本代码包提供核心方法、配置和轻量复现索引，不包含原始流量特征或大型数据文件。请从下列来源自行下载，并放在代码包以外的独立数据目录。本文三个主队列是 **TON、RT、CIC39**；CIC46只用于历史标签量诊断，不与CIC39主对照混用。

本说明依据原实验下载清单、固定配置及已保存的文件校验值整理；来源主页于2026年11月6日复核。本次整理没有重新下载大型数据、重新训练或重新评估模型。部分网页不提供可读取的固定版本页面，固定文件版本以本包配置及历史清单为准。

## 1 获取与放置步骤

1. 先选择一个队列。建议同门首次使用时从较小、直接下载的TON或RT开始。
2. 从本说明的实际来源下载对应文件。复现已有表格时应匹配实际文件和SHA256，不要仅凭“同一数据集名称”替换为另一特征版本。
3. 将原始文件解压、按下列结构放入独立目录；运行时把该队列目录作为`data-root`传入，具体命令见项目README。配置中的`source_files[].relative_path`相对于该目录解析。
4. 保持CSV原始字节、表头、行序和换行，不要先用Excel重存。用配置记录的SHA256核对文件，再执行数据准备。版本不匹配时先查清差异，不修改预期哈希来跳过检查。
5. 数据处理后会生成工作文件；工作目录和数据目录应分别指定，防止把下载数据误放进代码仓库。首次完整重训仍需要相应时间和内存，本包不承诺任意环境下得到逐位一致结果。

示例目录（盘符和最外层目录可自行改动）：

```text
E:/IoTData/
  ton_iot/                         <- TON的data-root
    TON_IoT Train_Test_Network.csv
  rt_iot2022/                      <- RT的data-root
    RT_IOT2022                     # 原始成员没有.csv后缀
  ciciot2023/                      <- CIC39的data-root
    Backdoor_Malware/
      Backdoor_Malware.pcap.csv
    Benign_Final/
      BenignTraffic.pcap.csv
    DDoS-HTTP_Flood/
      DDoS-HTTP_Flood-.pcap.csv     # 文件名中保留末尾的连字符
    MITM-ArpSpoofing/
      MITM-ArpSpoofing.pcap.csv
    XSS/
      XSS.pcap.csv
    ...                           # 其余目录和文件以配置中的34项为准
```

CIC39从镜像解压后常带一层`data/`目录：若文件实际位于`E:/IoTData/ciciot2023/data/XSS/XSS.pcap.csv`，则应把`E:/IoTData/ciciot2023/data`作为该队列的`data-root`，不必移动或改写原文件。

Windows可用以下命令只读核对一个文件：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'E:/IoTData/rt_iot2022/RT_IOT2022'
```

## 2 TON主队列

- 下载该记录中的`TON_IoT Train_Test_Network.csv`即可，不需要下载记录内的其他数据集、笔记本或压缩包。

## 3 RT-IoT2022主队列

- 官方来源：[UCI条目942](https://archive.ics.uci.edu/dataset/942/rt-iot2022)。
- 数据DOI：[10.24432/C5P338](https://doi.org/10.24432/C5P338)。
- 官方压缩包：[rt-iot2022.zip](https://archive.ics.uci.edu/static/public/942/rt-iot2022.zip)。
- 解压后使用文件`RT_IOT2022`，不要为其强行添加后缀；这是CSV格式文本。
- 配置：`configs/rt_iot2022.json`。UCI页面声明CC BY 4.0，使用时按其推荐方式引用。

| 文件 | 字节数 | SHA256 |
|---|---:|---|
| `rt-iot2022.zip` | 3,445,559 | `bcaa24d62abbb1215be576d5cf9c02dfcb0bb7c4c2f5a00e03055afaa1ed109e` |
| 解压成员`RT_IOT2022` | 54,781,794 | `956956c09c1764584fa08acd0f6876475626bcedcd6a6b1f8c492c2e9a2089ea` |

官方数据有123,117条记录、83个原始预测字段。冻结处理排除行号、目标列和两端端口，使用81个原始预测字段后再进行类别编码；编码后的维数与81并非同一概念。`Attack_type`为标签列；`MQTT_Publish`、`Thing_Speak`和`Wipro_bulb`映射为正常业务，其余按配置保留原攻击标签。

本研究的两个指定类别是**慢速连接耗尽攻击**（`DDOS_Slowloris`）和**ARP投毒攻击**（原始拼写`ARP_poisioning`）。RT数据不含跨站脚本标签，不能把此处结果写成跨站脚本检出率。固定研究队列为14,990条，不是UCI全库的自然类别比例。

## 4 CICIoT2023的39特征主队列

- 原始数据官方说明：[UNB CICIoT2023](https://www.unb.ca/cic/datasets/iotdataset-2023.html)。
- 原始论文：[10.3390/s23135941](https://doi.org/10.3390/s23135941)。
- 本实验实际来源：[Kaggle — Large-Scale Attacks in IoT Environment](https://www.kaggle.com/datasets/nikitamanaenkov/large-scale-attacks-in-iot-environment)，发布账号`nikitamanaenkov`，**固定第1版**；历史归档最后更新时间为2025年5月7日。
- 配置：`configs/ciciot2023.json`。其中`source_files`列出全部34个相对文件路径、标签和各自SHA256；下载后逐项核对。镜像页面声明CC BY 4.0，仍应按原始发布者和镜像的适用条款使用。

冻结文件选择规则：每个原生类别目录按完整远程文件名作字典序排序，仅取第一个完整CSV，共34个文件；选择在读取数据行和模型结果前冻结。不能按实验效果挑换文件，也不需要下载整个官方大库来运行这一研究队列。Kaggle可能要求登录或配置其下载工具，按网站当前流程操作；本包不包含账户令牌。

所选34个原始文件合计851,644,015字节、4,343,217条记录。数值非有限记录统一移除121条后剩4,343,096条；经固定去重、类别限量和整组恢复形成85,774条研究记录、84,288个分组。CSV本身仅含数值特征，标签来自被冻结的类别目录及配置映射，目录名称不能作为模型输入。

该输入是**39特征公开镜像表示**，与原始论文描述的46特征表示不同。不要把官方46特征CSV、其他镜像合并CSV或任意随机分片直接替换进当前配置。指定重点类别是跨站脚本（`XSS`）与中间人ARP欺骗（`MITM-ArpSpoofing`）；正常目录`Benign_Final`对应配置中的`BenignTraffic`标签。特征名和大小写按配置保留。

当前未证明这些镜像文件与CIC官方分发逐字节相同；镜像内部及跨镜像校验不等于官方一致性证明。本研究只使用冻结34文件与受控队列，不代表完整CICIoT2023或真实部署类别比例。

## 6 索引、标签预算与结果解释

`reference/<队列>/splits/*.npz`是轻量划分记录，仅含原始行号、分组和哈希等元数据，不含原始流量特征。它们用于对照恢复的分组角色和记录次序。TON额外依赖第2节的冻结队列索引。

RT/CIC39的冻结预处理先统一移除数值非有限记录，对数值做带符号`log1p`变换并转为规范`float32`，再与类别字段一起构造输入哈希。按类别保留最小哈希的有限输入，随后恢复这些输入对应的全部标签。同输入同标签保留首个代表；同输入不同标签全部保留在同一分组。整组恢复后个别类别可超过初始限量。源、验证、目标池与测试按整组隔离，类别编码及距离归一化遵循源集拟合规则。

70条表示**全部类别合计的新增目标池标注**，不是70条中间人样本，也不是整个研究仅有70条标签。源标签和2,100条历史验证标签另计。五次配对划分存在重叠，公开数据曾参与开发；本包用于复现受控回顾性流程，不能据此宣称时间外推、设备外推或部署盲测能力。重跑时请保留全部种子及失败记录，不挑选有利重复。
