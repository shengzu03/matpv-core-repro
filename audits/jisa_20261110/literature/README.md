## 2. 能决定贡献边界的差异

| 维度 | HCE-Boost [H] | PS-CAHE [P] | 本文 |
|---|---|---|---|
| 监督设定 | 全监督类别完整 | 训练覆盖五类 | 源训练缺目标类；50+20新增标签 |
| 修正机制 | 验证触发组专家 | OOF选类别对、类别条件概率融合 | 记忆后接二分类补认 |
| 输出约束 | 保持每次更新的组概率质量 | 全类概率融合后argmax | 相对图阶段仅C→f，保留0/g/f |
| 报警与定类 | 已区分组检测/子类纠正 | 已分别审计Normal↔Attack | 明确报警内受限补认 |
| 三项改标审计 | 未见同型账本 | 已有改对、改坏、错改错 | 针对目标补认计数并分析来源 |
| 成本界限 | 未见同型界限 | 未见同型界限，已讨论成本验证 | 本次增加假设成本比边界 |

详细证据位置与主张边界见06号CSV。HCE的概率质量守恒不等于硬标签报警集合不变；这是约束性质的数学区别，并非性能优劣判断。PS的“选择混淆对”排除Normal，不代表其推断具有报警内硬路由；其两个基模型仍共同预测。

## 3. 必须收紧的创新主张

最关键发现是PS-CAHE第5.9节/Table 14已按“改对、改坏、错改错”审计逐条改标。HCE-Boost也已明确区分组检测与子类别纠正。因此，A/B/C账本、“报警与定类是两回事”、局部专家及受约束纠错，均不能单独写成本文首次。

相对这两篇，本文可核实的差异是：源训练角色中目标类缺失、50+20分阶段追加监督、报警内单向改标约束，以及在该协议下联合报告恢复与错误改标并给出假设成本边界。这是一组具体设定与实证分析差异，不能仅凭两篇对照升级成全球首个任务或新理论。
